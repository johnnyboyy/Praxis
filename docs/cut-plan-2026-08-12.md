# Praxis cut plan — 2026-08-12

**Status: EXECUTED 2026-08-12** (laps 1–6, one commit per lap/pair; see git log
`cut:`-prefixed commits). Deviations from the plan as written:
- Laps 2+3 landed as one commit (the evicted verifiers land in the plugin they move to).
- `policy.py` was deleted in Lap 1 (orphaned once its only consumers — the executor loop and
  run_dag — were gone); `views.py` shrank to `cost()` for the same reason.
- The `verify`/`close` hook steps lost their firing points with the engine; the contract now
  fires `unit-close` only (docs/plugins.md updated).
- Lap 5 additionally restored the per-phase composition seam on the resumable path:
  `next_phase` now gathers contributors with `phase_name` set and returns a per-phase overlay.
- tdd-unit moved to `plugins/coding-process/` (new), not into an existing plugin.

Module-by-module reduction plan. Companion to `review-2026-08-12.md` (F1/F2/F5 are resolved
here by subtraction). Principle: **core owns the unit discipline — frame, lease, compose,
step through gates, journal. Everything with an opinion in it (workflows, gate forms,
judgment) is plugin content.**

## Evidence base

- This repo's journal (169 events) is 100% inline unit-graph flow (`unit.proposed/framed`,
  `handoff.pulled`, `unit.done`). Zero `phase.*` events, zero mints, three `conductor.gap`s.
- Plugins consume `phase_name` and `fact` edges heavily (uiux, planner, writing, monorepo).
  Nothing consumes stance (`situation.phase`) or `agent-choice` edges outside `tests/`.
- Review F2: the detached ORCHESTRATOR path cascade-stalls; the inline path is the real one.

## End state

One execution model: **the model executes, praxis referees.** MCP surface:
`init`, `register_plan`, `next_handoff`, `next_phase`, `record_phase`, `close_unit`,
`record_receipt`, `escalate_unit`, `plan_status`, `conductor_status` (15 tools → 10).
Core ~3,000 lines (from ~5,400 + scripts). Workflows, gate forms, and the rebuild triple
live in bundled plugins a root opts into.

## Sequencing

Land the in-flight rename/prose-diet work **first** — this plan rewrites `run.py`,
`isolation.py`, and the docs wholesale; prose edits rebased into deleted code are wasted.
Laps are ordered so each lands independently green (`pytest` after each).

## Lap 1 — Delete the in-process execution engine (resolves F2)

The detached path is a second, unreliable engine: praxis spawning `claude -p` children.
Fan-out belongs to the harness (Agent tool, `isolation: "worktree"` per BACKLOG).

| Target | Action |
|---|---|
| `cascade.py`, `orchestrate.py`, `schedule.py` | **delete** |
| `mcp_server.py` | remove the `plan` and `conduct` tools |
| `conduct.py` | remove `run_tasklist_detached` + the `run_unit`-driving single-unit path; keep `register_plan` / `next_handoff` / `close_unit` / `record_receipt` / `escalate` / phase-walk glue |
| `run.py` | remove `run_unit`, `Executor` / `InlineExecutor` / `SubprocessExecutor`, the retry loop; **keep** `Receipt`, `Unit`, `Plan`, `Verdict`, the `Verifier` protocol, `CallableVerifier` / `CommandVerifier`, `verifier_from_test_cmd`, `verifiers_for_workflow` |
| `workflow_run.py` | remove the synchronous `run_workflow` loop; keep `decide_step`, `gate_for`, `_incoming` (promote to public — `phase_walk` imports them) |
| `skills/orchestrate` | rewrite to drive harness Agent fan-out over `register_plan` / `next_handoff` (it already describes the inline flow) |
| tests | delete `test_async`, cascade/orchestrate/schedule suites; **port** `run_workflow` edge-routing tests (incl. fact-edge cases) to `phase_walk`/`decide_step` before deleting the loop |

Risk: fact-edge routing for uiux/planner workflows may currently be exercised only through
the sync loop's tests — porting those tests is the gate for this lap.

## Lap 2 — Evict the verifier zoo from core (resolves F5)

Core keeps the invariant (close only through a passed gate) and the plumbing
(`Verifier` protocol, `CallableVerifier`, `CommandVerifier`, `verifier_from_test_cmd`).

**Delete from `run.py`** (~450 lines): `coverage_verifier`, `mutation_verifier`,
`ts_mutation_verifier`, `adequacy_verifier`, `coverage_diff_verifier`, the held-out runners,
the AST surface extractor, and the hand-rolled TS `.d.ts` parser (`_ts_parse_dts`,
`_balanced_parens`, `_split_top_level`, …). The Python-side rebuild verifiers move to the
rebuild plugin (Lap 3); the TS parser is deleted outright — revive from git if a TS rebuild
consumer ever appears.

`verifiers_for_workflow` loses its hardcoded `rebuild-triple` special case; the default gate
for every edge type is `verifier_from_test_cmd` from policy/config, and a plugin supplies
richer verifiers for its own workflows.

## Lap 3 — Rebuild triple becomes a bundled plugin

Keep in core: `EdgeType` create/carry/extract + the `GATES` mapping — the context-boundary
typing is the system's best idea and costs ~20 lines. Move the enforcement machinery:

| Target | Action |
|---|---|
| `isolation.py`, `rebuild_spec.py` | **move** to `plugins/rebuild/` |
| `hooks/tripwire_log.sh` | move with it; its `hooks.json` entry is documented as part of installing the rebuild plugin |
| `extract` / `synthesize` / `coverage-diff` phases + `rebuild-triple` workflow | move out of the seed library into the plugin's `phases()` / `workflows()` |
| rebuild verifiers from Lap 2 | land here |

## Lap 4 — Seed workflows shrink to one default loop (resolves F1)

Core seed becomes: phases `{plan, implement, verify, fix, close}` and the single workflow
**build-verify** (implement → verify → fix-loop → close) — the always-present front door.
`tdd-unit` (and its phases `write-tests` / `refactor` / `test-cleanup`) moves to a bundled
`plugins/coding-process/`. This resolves F1 differently than the review proposed: the front
door is the degenerate loop, not the planner's `intake` — `intake` stays plugin content, and
the planner plugin keeps it alongside its judgment domains.
